# חוג לכל ילד — בוט ווטסאפ

בוט ווטסאפ לתוכנית העירונית "חוג לכל ילד" של עיריית קריית אונו.
עונה להורים על שאלות מתוך התקנון והשו"ת, מפנה למפעילי החוגים, ומעביר לנציג
אנושי כשצריך. מבוסס על Claude (Anthropic API).

---

## עקרון התכנון המרכזי: המידע האישי לא עוזב את העירייה

זו הדרישה שהכתיבה את כל הארכיטקטורה. הבוט צריך גם זיכרון מלא של השיחות וגם
שמידע על תושבים לא ידלוף החוצה — ושני אלה נראים סותרים. הפתרון הוא הפרדה:

```
הודעה מהורה
      │
      ▼
┌──────────────────┐
│ שכבת ניקוי       │  ת"ז, טלפון, אימייל, כתובת, שם מלא, מספרי כרטיס
│ src/privacy      │  מוחלפים בסמנים:  [[ID_1]] [[PHONE_1]] [[NAME_1]]
└────────┬─────────┘
         │
    ┌────┴─────────────────────────┐
    ▼                              ▼
┌─────────────────┐      ┌──────────────────────┐
│ Claude API      │      │ מסד נתונים מקומי     │
│                 │      │                      │
│ רואה רק את      │      │ הטקסט המלא, מוצפן    │
│ הטקסט המנוקה.   │      │ AES-256-GCM.         │
│ לעולם לא רואה   │      │ המפתח אצל העירייה    │
│ ת"ז או טלפון.   │      │ בלבד.                │
└────────┬────────┘      └──────────────────────┘
         │
         ▼
┌──────────────────┐
│ החזרת הערכים     │  [[NAME_1]] ← "דנה כהן"
└────────┬─────────┘
         ▼
   תשובה להורה
```

מה זה אומר בפועל:

- **ל-Anthropic נשלח רק טקסט מנוקה.** תעודות זהות, טלפונים ואימיילים מוחלפים
  בסמנים לפני היציאה. יש שסתום ביטחון (`assertClean`) שמפיל את הבקשה אם מזהה
  שרד את הניקוי — עדיף כישלון רועש מדליפה שקטה.
- **מספר הטלפון של הפונה נשמר מוצפן בלבד.** בכל הטבלאות, בכל הלוגים ובכל
  הדוחות מופיע רק שם מדומה (HMAC של המספר עם סוד מקומי).
- **השיחה נשמרת במלואה, מוצפנת.** אפשר לשלוף אותה בכל רגע לצורך טיפול בפנייה.
- **הדוחות הפנימיים רצים על הטקסט המנוקה.** אפשר להריץ דוח ולהעביר אותו הלאה
  בעירייה בלי לחשוף פרטי תושבים.
- **תוכן גולמי נמחק אוטומטית** אחרי `RAW_RETENTION_DAYS` (ברירת מחדל 180 יום),
  והטקסט המנוקה נשאר לניתוח. אפשר לכבות עם `0`.

### מה שעדיין צריך לדעת

- **זיהוי שמות הוא הסתברותי.** ת"ז, טלפון ואימייל נתפסים בדיוק גבוה מאוד. שם
  מלא נתפס רק כשהוא מוצג במפורש ("קוראים לי...", "הבן שלי..."). שם שמוזכר
  באמצע משפט חופשי עלול לעבור. אם זו דרישה מחייבת, צריך להוסיף שכבת NER.
- **בקשו מ-Anthropic הסדר Zero Data Retention.** כברירת מחדל, קלט ופלט ב-API
  אינם משמשים לאימון ונשמרים 30 יום. ארגון יכול לבקש שלא יישמרו כלל. לגוף
  ציבורי זה שווה את הפנייה — דרך נציג המכירות בקונסולה.
- **המפתחות הם נקודת הכשל היחידה.** אובדן `DATA_ENCRYPTION_KEY` = אובדן כל
  ההיסטוריה, בלי דלת אחורית. ראו "ניהול מפתחות" למטה.

## הקמה

### 1. דרישות מקדימות

| מה | איפה | הערות |
|---|---|---|
| מפתח Anthropic API | `console.anthropic.com` | **לא** מנוי claude.ai. זה מוצר נפרד בתשלום לפי שימוש. |
| WhatsApp Business Account | `business.facebook.com` | דורש אימות עסק. תהליך של ימים עד שבועות — התחילו מוקדם. |
| מספר טלפון ייעודי | — | לא יכול להיות מספר שכבר מחובר לאפליקציית ווטסאפ רגילה. |

### 2. התקנה

```bash
npm install
cp .env.example .env
npm run keys        # מייצר את מפתחות ההצפנה
```

העתיקו את שני המפתחות לתוך `.env`, ומלאו את שאר השדות.

> **שימו לב:** משתני סביבה שכבר מוגדרים במערכת גוברים על `.env`. אם ערך לא
> "תופס", בדקו קודם `echo $VAR`.

### 3. חיבור ה-Webhook למטא

בפאנל של מטא, תחת WhatsApp → Configuration:

- **Callback URL**: `https://<הכתובת-שלכם>/webhook`
- **Verify token**: אותה מחרוזת שהגדרתם ב-`META_VERIFY_TOKEN`
- **Webhook fields**: לסמן `messages`

מטא דורשת HTTPS עם תעודה תקפה. לפיתוח מקומי אפשר `ngrok http 3000`.

### 4. הרצה

```bash
npm run dev      # פיתוח
npm run build && npm start
docker compose up -d --build
```

**מומלץ להתחיל עם `DRY_RUN=true`.** במצב הזה הבוט מקבל הודעות, מריץ את המודל
וכותב הכול למסד הנתונים, אבל לא שולח תשובות בפועל. אפשר לראות מה הוא *היה*
עונה, לפני שהורה אמיתי רואה משהו.

## איפה זה גר

**הקוד ובסיס הידע** נמצאים ב-GitHub, ברפו `nadaveron/Nadav`. זה המקור היחיד,
והוא בענן: כשמתחלפים אנשים בארגון או כשאתם מחליפים מחשב, מעבירים גישה לרפו
וזהו. אין קובץ קריטי שיושב על מחשב אישי.

**הבוט עצמו** צריך לרוץ על שרת בענן שזמין 24/7 — מטא שולחת webhook בכל הודעה,
ואם השרת כבוי ההודעה נופלת.

| אפשרות | יתרון | חיסרון |
|---|---|---|
| Render / Railway | פריסה מ-GitHub בכמה קליקים | צריך להוסיף Persistent Disk בתשלום |
| Google Cloud Run | זול מאוד בנפח הזה | דיסק ארעי — חובה לחבר אחסון קבוע |
| שרת של העירייה | המידע לא יוצא מהתשתית העירונית | מישהו צריך לתחזק אותו |

> ⚠ **הדבר החשוב ביותר בפריסה:** מסד הנתונים הוא קובץ בתיקייה `data/`. ברוב
> שירותי הענן דיסק הקונטיינר הוא ארעי, ו**כל פריסה מחדש תמחק את כל היסטוריית
> השיחות**. חובה לחבר volume קבוע לנתיב `/app/data`, ולהגדיר גיבוי שלו.

### ניהול מפתחות

`DATA_ENCRYPTION_KEY` ו-`PHONE_HASH_PEPPER` הם הדבר היחיד שאי אפשר לשחזר.
לא ב-git, לא בקובץ על המחשב, לא בוואטסאפ. הכניסו אותם ל-Secret Manager של
שירות האירוח, ושמרו עותק במנהל הסיסמאות הארגוני — אצל **שני אנשים לפחות**,
כדי שהתוכנית לא תלויה באדם אחד. אל תשמרו אותם באותו מקום שבו נשמרים הגיבויים
של מסד הנתונים; מי שמשיג את שניהם מקבל את הכול.

## מילוי בסיס הידע

תיקיית `knowledge/` היא מה שהבוט יודע. כל שינוי שם משנה את התנהגותו.

| קובץ | מה נכנס |
|---|---|
| `00-overview.md` | תיאור התוכנית, זכאות, מה כולל השובר, תאריכים |
| `10-takanon.md` | נוסח התקנון המאושר, במלואו |
| `20-faq.md` | שאלות ותשובות — **הקובץ שמשפר את הבוט הכי מהר** |
| `30-operators.md` | פרטי קשר של המתנ"ס, הקונסרבטוריון, הבריכה ואגף הספורט |
| `40-escalation.md` | מתי להעביר לנציג |

**מצב נוכחי:** התקנון והשו"ת הוזנו במלואם מתוך המסמכים הרשמיים של תשפ"ז.
מה שעדיין חסר הוא פרטי הקשר של הגופים המפעילים ורשימת החוגים שלהם — ראו
`OPEN-QUESTIONS.md`.

**כל שדה שמסומן `<<< למילוי >>>` הוא שדה שהבוט יגיד עליו "אין לי את המידע
הזה" ויעביר לנציג.** זה מכוון: עדיף הסלמה מיותרת מתשובה מומצאת. לפני העלייה
לאוויר, עברו על כל הסימונים ועל `OPEN-QUESTIONS.md`.

אחרי עריכה צריך להפעיל מחדש את השירות. ב-Docker Compose התיקייה ממופה פנימה,
אז `docker compose restart bot` מספיק — בלי בנייה מחדש.

## תפעול שוטף

```bash
npm run report -- summary            # תמונת מצב כללית
npm run report -- escalations 30     # למה הבוט הסלים — לפי סיבה
npm run report -- questions 30       # מה הורים שאלו בפועל
npm run report -- cost 30            # הערכת עלות
npm run report -- conversation 42    # שיחה מלאה (מפוענחת) לטיפול בפנייה
```

`escalations` הוא הדוח שכדאי להסתכל בו כל שבוע בחודשיים הראשונים: סיבה שחוזרת
הרבה היא כמעט תמיד שאלה שחסרה ב-`20-faq.md`. כל הוספה שם מורידה את עומס
ההסלמות בשבוע שאחריה.

### כשהבוט מעביר לנציג

הבוט משתיק את עצמו לאותה שיחה למשך `HUMAN_HANDOFF_HOURS` (ברירת מחדל 24),
ממשיך לתעד את מה שההורה כותב, ושולח לך התראה. אחרי שהזמן עובר הוא חוזר לענות
מעצמו. אין צורך בפעולה ידנית.

מילים שמעבירות לנציג מיד, בלי לשאול את המודל: "נציג", "בן אדם", "אנושי",
"לדבר עם מישהו" ועוד. הרשימה ב-`src/handler.ts`.

## התראות שעובדות 24/7

**הבוט עונה להורים בכל שעה, תמיד.** אין שום מגבלה על זה. כשהורה שולח הודעה
בשבת בלילה אחרי 36 שעות שקט, ההודעה שלו פותחת חלון חדש והבוט עונה כרגיל.

המגבלה של מטא חלה רק על הודעות ש**העסק יוזם** — ואצלנו זו רק ההתראה אליך על
הסלמה. אם לא כתבת למספר העסקי ב-24 השעות האחרונות, התראת טקסט חופשי תיכשל.

**הפתרון: Message Template מאושרת.** תבנית מאושרת נשלחת בכל שעה, בלי קשר
לחלון. כך מגדירים אחת:

1. Meta Business Manager → WhatsApp Manager → Message Templates → Create.
2. קטגוריה: **Utility** (לא Marketing — Utility מאושרת מהר יותר ואינה
   נחשבת הודעה שיווקית).
3. שפה: עברית.
4. גוף ההודעה, עם שלושה משתנים בסדר הזה:

   ```
   פנייה חדשה בתוכנית "חוג לכל ילד" - {{1}}
   טלפון הפונה: {{2}}
   פרטים: {{3}}
   ```

5. אחרי האישור (בדרך כלל דקות עד שעות), הזינו ב-`.env`:

   ```
   META_ALERT_TEMPLATE=<שם התבנית שיצרתם>
   META_ALERT_TEMPLATE_LANG=he
   ```

הבוט ישתמש בתבנית אוטומטית. **כל עוד `META_ALERT_TEMPLATE` ריק**, ההתראות
נשלחות כטקסט חופשי ויעבדו רק בתוך החלון.

בכל מקרה, ההסלמה עצמה **תמיד** נשמרת במסד הנתונים לפני שההתראה נשלחת. גם
אם ההתראה נכשלה, הפנייה לא הולכת לאיבוד — היא מופיעה ב-`npm run report --
escalations`, וכשל שליחה נרשם כאירוע `alert_failed`.

## מגבלות ידועות

1. **טקסט בלבד בהודעות נכנסות.** ראו סעיף 2.
2. **טקסט בלבד.** תמונות, הקלטות קוליות ומסמכים מקבלים תשובה שמסבירה שצריך
   לכתוב במילים. הוספת תמלול קולי היא הרחבה טבעית — הורים שולחים הרבה הקלטות.
3. **הבוט אינו מבצע פעולות.** הוא לא רושם לחוג, לא בודק זמינות ולא מבטל.
   רק עונה ומפנה. חיבור למערכת ההרשמה הוא פרויקט נפרד.
4. **תמונת ה-Docker לא נבנתה ולא נבדקה** — בסביבה שבה נכתב הקוד לא היה דימון
   דוקר. הריצו `docker compose up --build` פעם אחת על השרת האמיתי לפני העלייה.

## עלות

בנפח שהוגדר — כ-1000 פניות בחודשיים הראשונים ופחות מכך עד סוף השנה:

| מודל | לשיחה | 1,000 שיחות |
|---|---|---|
| Opus 5 (ברירת מחדל) | ~0.32 ₪ | ~320 ₪ |
| Sonnet 5 | ~0.13 ₪ | ~130 ₪ |
| Haiku 4.5 | ~0.06 ₪ | ~65 ₪ |

כלומר עלות ההרצה השנתית היא מאות שקלים בודדים. שני דברים מוזילים משמעותית:
בסיס הידע נשמר ב-prompt cache משותף לכל הפונים (`ttl: 1h`, מתאים לקצב פניות
של תוכנית עירונית), ו-`CLAUDE_EFFORT` שולט בעומק החשיבה ובעלות בלי להחליף
מודל.
